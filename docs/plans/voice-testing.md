# Тестирование голоса ИИ-учителя

Как проверить весь голосовой путь «микрофон → распознавание → лента → ответ учителя» без телефона и без ПК друга,
и как снять живой замер на сервере. Контракт — «Голос» v1 (`.tmp/spec-voice.json`, раздел `contract`):
`POST /stt` (WAV PCM16 моно 16 кГц, 0,3–25 с), `GET /stt/health`, поле `stt` в `/health`.

## Команды

| Команда | Что делает | Сеть |
| --- | --- | --- |
| `npm run test:voice-wer` | юнит WER/CER: нормализация (ё, uz-апострофы ʻ ’ ' \`), числа цифры↔слова ru/uz/en, формулы через `fixTranscript` | нет |
| `npm run voice:audio` | тестовое аудио Edge Neural TTS: 30 фраз × 3 языка × варианты → `.tmp/voice-audio/<lang>/<id>-<variant>.wav` + `manifest.json`; кэш по хешу фразы | Edge TTS |
| `npm run voice:audio -- --fixtures` | ещё и короткие клипы в `scripts/voice/fixtures` (≤ 1,5 МБ, лежат в репозитории) | Edge TTS |
| `npm run voice:mock` | заглушка мозга на `http://127.0.0.1:8796`: `/health`, `/stt`, `/stt/health`, `/chat` (SSE «Понял: …») | нет |
| `npm run voice:eval -- --with-mock` | оценка `/stt` против заглушки, поднятой на свободном порту (проверка контракта) | нет |
| `npm run voice:eval -- --url=<мозг>` | оценка настоящего сервера: WER, язык, тишина, формулы, p50/p95, коды ошибок | да |
| `npm run e2e:voice` | настоящий урок в Chromium с фейковым микрофоном + заглушка мозга, сценарии a–j | нет |
| `npm run e2e:voice -- --only=none --live=msedge` | живой ручной режим: настоящий Web Speech (Edge/Chrome), фразу говорит человек, мозг — заглушка | да (Web Speech) |

Без сети работают `test:voice-wer`, `voice:mock`, `voice:eval -- --with-mock --manifest=scripts/voice/fixtures/manifest.json`
и `e2e:voice` (клипы из `scripts/voice/fixtures`).

## Тестовое аудио (`voice:audio`)

- Фразы — `scripts/voice/phrases.mts`: по 30 на язык (вопросы по химии, формулы, числа, команды «стоп / повтори /
  следующий вопрос», бытовые фразы); голоса ru Dmitry + Svetlana, uz Sardor + Madina, en Guy + Aria.
- Синтез — протокол Edge TTS из `src/learn/learnEdgeTtsNode.ts` (mp3 24 кГц) → ffmpeg Playwright
  (`%LOCALAPPDATA%\ms-playwright\ffmpeg-*\ffmpeg-win64.exe`) → WAV PCM16 моно 16 кГц (для `/stt`)
  и 48 кГц (для фейкового микрофона Chrome, `--all48`).
- Варианты: `clean`, `snr20`, `snr10` (белый шум), `class` (два других голоса на −12 дБ + белый шум 20 дБ), `quiet` (−18 дБ),
  `padded` (тишина 1,5 с до и 2 с после), `long` (склейка ~45 с — сервер обязан ответить 413), `silence` (5 с),
  `noise` (5 с), `echo` (фраза учителя ru-Dmitry как вход микрофона).
- Повторный запуск берёт mp3 из кэша `.tmp/voice-audio/cache` (ключ — хеш голоса и текста); `--force` — заново.

## Оценка сервера (`voice:eval`)

```
npm run voice:eval -- --url=https://<funnel-адрес>  [--concurrency=1] [--load=4] [--only=ru,uz] \
     [--variants=clean,snr10] [--limit=N] [--partial] [--json=.tmp/stt-eval.json] [--no-thresholds]
```

1. Контракт: поля ответа 200, `partial=1`, 400 `bad_audio` на 48 кГц, 400 `too_short`, 400 на плохую `session`,
   415 на `text/plain`, 413 `too_long` на 45 с, 429 `busy`/`rate` с `Retry-After`, у заглушки ещё 503 (`mode=down`).
2. Все клипы манифеста при `concurrency=1` (задержка), затем `--load=4` параллельно.
3. `--partial`: первые 1,2 / 2,4 / 3,6 с клипа с `partial=1` — текст должен быть префиксом финального (WER ≤ 30 %).

### Пороги (выход 1 при нарушении)

| Что | Порог |
| --- | --- |
| WER чистые клипы | ru ≤ 10 %, uz ≤ 15 %, en ≤ 15 % |
| WER при SNR 10 дБ | ≤ 2 × чистого того же языка |
| тишина / шум | пустой текст ≥ 98 % клипов |
| язык (речь ≥ 1,5 с) | ≥ 95 % по каждому языку |
| формулы после `fixTranscript` | ru ≥ 85 %, uz/en ≥ 70 % точных совпадений |
| p95 `/stt` | ≤ 800 мс при concurrency 1, ≤ 1,5 с при 4 |
| 45 с | 413 `too_long` |

### Как читать отчёт

- Таблицы «WER по языкам / вариантам / категориям»: «клипов», «слов» — объём, WER — корпусный (сумма правок / сумма
  слов эталона), CER — по символам. Сравнение — минимум из вариантов «как есть», «цифры→слова», «слова→цифры»,
  «после `fixTranscript`», поэтому «18» и «восемнадцать» не считаются ошибкой.
- «задержка c=1»: клиент — полный круг HTTP, сервер — `ms.total` из ответа. Большая разница = сеть/Funnel.
- `--json=` пишет все строки (id, вариант, эталон, текст, WER, lang, ms) — удобно искать худшие клипы.

### Живой замер на сервере друга

Делает владелец (агенты сервер друга не трогают):

1. На ПК друга после слияния server-stt: `GET https://<funnel>/stt/health` → `available: true`.
2. На своём ПК: `npm run voice:audio` (один раз), затем
   `npm run voice:eval -- --url=https://<funnel> --concurrency=1 --load=4 --json=.tmp/stt-eval-live.json`.
3. Ограничения сервера: 30 финальных запросов в минуту на `session` — скрипт выдерживает паузы по `Retry-After`;
   полный прогон ~600 клипов занимает ~20 мин. Для быстрого замера: `--variants=clean,snr10 --limit=40`.
4. Результат приложить сюда таблицей (дата, движок, устройство, WER по языкам, p50/p95).

## Заглушка мозга (`voice:mock`)

`npm run voice:mock [-- --port=8796] [--manifest=.tmp/voice-audio/manifest.json] [--mode=slow] [--quiet]`

- Текст распознавания: заголовок `X-Mock-Text` → хеш тела по манифесту → `X-Mock-Clip: <id>` (выравнивание сегмента
  с зарегистрированным клипом по огибающей громкости, нужно e2e) → пусто.
- Режимы `?mode=` у `/stt` или `POST /mock/mode?mode=`: `normal`, `slow` (1,5 с), `down` (503 + `Retry-After: 10`,
  `available: false` в health), `rate` (каждый нечётный запрос сессии → 429 `Retry-After: 1`).
- Служебное: `GET /mock/stats`, `POST /mock/reset`.
- Отладка сайта без ПК друга: `npm run voice:mock`, затем `VITE_BRAIN_URL=http://127.0.0.1:8796 npm run dev`
  (в PowerShell: `$env:VITE_BRAIN_URL='http://127.0.0.1:8796'; npm run dev`); CORS заглушка разрешает с любого Origin.
  Говорить в настоящий микрофон: заглушка вернёт пустой текст (нет клипа) — для текста добавьте заголовок
  `X-Mock-Text` или прогоните `npm run e2e:voice`.

## E2E через интерфейс (`e2e:voice`)

```
npm run e2e:voice [-- --only=a,b,f] [--base=http://127.0.0.1:5173] [--port=5197] [--lead=6] [--headed]
                     [--strict] [--live[=msedge,chrome]] [--live-brain] [--keep]
```

- Скрипт сам поднимает `vite` (dev) на `--port` (или берёт готовый сайт `--base`) и заглушку на свободном порту.
- Chromium (`channel: chromium`, новый headless) запускается на каждый сценарий с
  `--use-fake-device-for-media-stream --use-fake-ui-for-media-stream --use-file-for-fake-audio-capture=<WAV>%noloop`.
  WAV 48 кГц собирается из `scripts/voice/fixtures`: тишина `--lead` секунд (учитель здоровается), фразы, хвост;
  лежит в `%TEMP%\atomlab-e2e-voice` (путь без кириллицы — флаг Chrome его не любит).
- Сайт находит мозг через `public/brain.json` — запрос перехватывается (`page.route`) и подменяется адресом заглушки;
  к `/stt` добавляется `X-Mock-Clip`. Код сайта не меняется.
- Урок `#/learn/g/g7/c/c1/s/s01?stt=server&debugVoice=1` → «Как проведём урок?» → «ИИ-учитель» →
  «Начать онлайн-диалог» → «Начать урок».
- Наблюдатель в странице (каждые 100 мс): лампы `voice-lamp-mic` / `voice-lamp-stt` (`data-state`), чип
  `voice-path-chip` (`data-path`), реплики `live-transcript-you` (до слияния — запасной селектор по ленте), ответы
  учителя, момент `getUserMedia`.

| Сценарий | Проверка |
| --- | --- |
| a | ru-клип → реплика ученика, WER ≤ 15 %, ≤ 4 с после конца звука; лампы «слышит»/«распознаю» горели; ответ учителя |
| b | uz и en клипы → текст и язык ответа `/stt` |
| c | тишина 5 с → 0 реплик, «распознаю» не красная, через 8 с нет жёлтой «не отвечает» |
| d | ~45 с непрерывной речи → ≥ 2 сегмента `/stt`, ни одного 413, объединённый WER ≤ 20 % |
| e | эхо фразы учителя во время озвучки → реплики нет (если браузер не озвучивал — «пропуск») |
| f | `getUserMedia` → `NotAllowedError` → баннер с «Повторить», текстовый ввод работает |
| g | `NotFoundError` → понятный баннер про микрофон, текстовый ввод работает |
| h | заглушка `down` → путь не `server` или баннер «сервер недоступен», текст работает |
| i | заглушка `rate` → 429, повтор после `Retry-After`, реплика дошла |
| j | `#/voice-check`: запись → текст и путь, «Скопировать отчёт» → JSON (`ua, path, brainUrl, levels, errors, text, lang`) |
| k | `--live`: настоящий Web Speech (Edge/Chrome), окно видимое, человек говорит фразу; только отчёт, не влияет на код выхода |

Статусы: `ok`, `FAIL`, `wait` — на странице нет элементов контракта (сайт ещё без site-voice; с `--strict` = провал),
`skip`. Скриншоты — `.tmp/e2e-voice/<сценарий>.png`, отчёт — `.tmp/e2e-voice/report.json`. Прогон a–j ≈ 4–5 мин.

### Результаты на этом ПК (12.10)

- `main` (886adefb, без site-voice): f — ok (баннер «Нет доступа к микрофону… Повторить», текст → «Понял: что такое
  валентность» от заглушки через настоящий `/chat`); a, g, j — «ждёт слияния».
- Черновик site-voice (ветка `worktree-wf_a7737235-6c4-3`, наложен на время прогона): c, f — ok; лампа «слышит»
  загорается на речи клипа, чип «Распознавание: сервер ATOMLAB», но сегмент в `/stt` не уходит (`uploadBytes: 0`) —
  a, i падают «нет реплики»; g — нет баннера на `NotFoundError`; h — путь остаётся `server`, хотя `/stt/health`
  отвечает `available: false`. Это задачи site-voice; e2e готов прогнать их после слияния.
- `--live` (Edge и Chrome, headless и с окном, мозг — заглушка): Web Speech возвращал текст, не имеющий ничего общего
  с клипом в фейковом микрофоне (WER 100–170 %). Причина: **Web Speech в Chrome/Edge слушает настоящий микрофон ПК
  по умолчанию**, флаг `--use-file-for-fake-audio-capture` действует только на `getUserMedia`. Значит:
  1) путь `web_speech` автоматически фейковым микрофоном не проверить — только вручную (`--live` теперь ждёт, что
     человек сам скажет фразу «молярная масса воды восемнадцать грамм на моль», и меряет WER);
  2) серверный путь (`getUserMedia` → WAV → `/stt`) e2e проверяет полностью — ради этого он и делается;
  3) живой режим отправляет звук комнаты в облачное распознавание браузера — запускать только у себя.
  Тексты из этих прогонов не сохранены (в них попал разговор в комнате).
