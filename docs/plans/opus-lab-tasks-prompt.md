## Кто ты и что делаешь

Ты — ведущий инженер и методист проекта ATOMLAB: школьный сайт по химии (Kimyo 7–11, RU/EN/UZ), React 19 + Vite 8 +
TypeScript 6 + three 0.184 / @react-three/fiber 9 / drei 10, статический GitHub Pages (без сервера). Отвечай и пиши
тексты по-русски.

Задача: сделать новый режим **«Решить в лаборатории»** — расчётная задача из учебника решается не на бумаге, а как
настоящий опыт в существующей 3D-лаборатории сайта (`#/vr-lab`). Ученик взвешивает на весах, отмеряет мензуркой,
проводит реакцию, собирает газ, читает показания приборов — и число ответа получает **из измерений**, а потом сверяет с
расчётом. 15 задач: по 5 из учебников 7, 8 и 9 классов, разной сложности. Качество — «как в реальной лаборатории»:
без отрыва от реальности, с настоящими погрешностями приборов, правильной химией, понятными инструкциями и без
единой ошибки.

Планка качества: это должно быть лучшее, что есть в школьном образовании по химии. Каждая деталь — как у
реального прибора (деления, цена деления, погрешность, мениск), каждая реакция — как в жизни (скорость, цвет,
тепло, запах — текстом), каждое число — проверяемо.

Главные факты оттуда, которые определяют работу:
1. **Опыт сейчас — анимация шагов по одному числу прогресса `p`, а не симуляция.** Количеств веществ (масса, объём,
   моли) в коде нет нигде.
2. **Ни один прибор не показывает число.** Весы — декор с текстурой «0.00 g» (`scene/LabEquipment.tsx:320–337`),
   мерный цилиндр — риски без цифр, уровни жидкостей — в метрах высоты (`TestTube.level`, `LiquidColumn.level`),
   перевода мл → высота нет. Мерной колбы, бюретки, газометра, 3D-термометра нет.
3. Шаг опыта засчитывается касанием/перетаскиванием нужной цели (`ExperimentRig.tsx act()`), проверки правильности
   количеств нет.
4. Допуск проверки ответа в тренажёре — ±0,8 % (`learnTaskProblems.ts:35–39`): погрешность реального прибора в него
   не укладывается.
5. Лаборатория читает из адреса только `exp` (и `q`, debug-флаги); результат опыта наружу не передаётся

6. Текстов задач в данных проекта нет — только в PDF учебников и в извлечённом тексте
   `scripts/kb/.cache/lines-g7.json`, `lines-g8.json`, `lines-g9.json` (поле `page` = номер страницы в книге).

Поэтому работа идёт в три этапа: **измерительный слой → 15 задач-опытов → интеграция и проверка.**

## Этап 1. Измерительный слой лаборатории (фундамент)

Сделай в `src/components/lab3d/` новый модуль `measure/` (чистая логика без React — отдельно, компоненты — отдельно),
чтобы опыт мог оперировать **количествами**, а приборы — **показывать числа**.

### 1.1. Модель количеств (`measure/quantities.ts`)
- Вещества и их свойства для 15 задач: формула, молярная масса (школьная), агрегатное состояние, плотность (для
  растворов — по w%), цвет, растворимость, для газов — Vm.
- Сосуд: тип (пробирка, стакан 100/250 мл, мензурка 50/100/250 мл, мерная колба 100 мл, коническая колба, фарфоровая
  чашка), геометрия (внутренний радиус/профиль), **функция мл → высота уровня и обратно** для каждой формы (для
  пробирки уже выведено: V ≈ 0,97 + 0,1882·(h_мм − 9); для остальных выведи из геометрии в `glassware.tsx` /
  `practicalware.tsx`). Исправь существующее расхождение: в `co2` налито ~10,6 мл при тексте «2–3 мл».
- Содержимое сосуда: список порций (вещество, масса/объём/моли, температура), агрегированные свойства (объём,
  цвет, муть, пузыри).
- Реакция: по стехиометрии из уравнения — расход и образование веществ по **недостатку**, выделение газа (моли →
  мл при н.у. и при комнатной температуре, см. 1.3), осадок (масса, объём слоя), тепло (ΔT по простому тепловому
  балансу, где задача этого требует — CaO + H₂O, нейтрализация), **кинетика по школьной картинке**: скорость как
  функция времени (Zn + HCl — пузырьки идут минуты, замедляясь; Al + H₂SO₄ разб. — почти не идёт без нагрева;
  Fe + CuSO₄ — минуты; AgCl выпадает мгновенно; CuSO₄·5H₂O обезвоживается при нагреве за ~1–2 мин с переходом
  синий → белый).
- Все функции чистые и покрыты тестом (`scripts/test-lab-measure.mts`): стехиометрия 15 задач даёт ответы учебника
  (таблица в разделе «15 задач»), мл ↔ высота обратимы, баланс масс сходится, недостаток определяется верно.

### 1.2. Приборы с показаниями (компоненты в `measure/instruments/`)
Каждый прибор — реальный школьный, с **ценой деления, диапазоном и погрешностью**, читается крупно и с 3D, и на
доске (HTML-дубль показаний для телефона и доступности):
- **Электронные весы** (0,01 г; до 500 г; ±0,01 г): дисплей — живая `CanvasTexture`, обнуление «T» (тара),
  показание меняется по мере насыпания/наливания; стабилизируется с задержкой ~0,5 с (как настоящие); перегруз —
  «Err». Заменяют декоративные `Scales` в `LabEquipment.tsx` (или ставятся на рабочее место как предмет
  `tool:scales`).
- **Мензурка (мерный цилиндр) 50 и 100 мл** (цена деления 1 мл; ±0,5 мл) и **стакан 100/250 мл** (риски с цифрами,
  грубые): цифры на шкале читаемы при крупном плане; **мениск** — читать по нижнему краю (подсказка учителя при первом
  использовании); объём, который налил ученик, определяется жестом «лей, пока держишь» (длительность/наклон →
  мл) с остановкой у нужной метки «магнитом» ±1 мл и возможностью долить/отлить пипеткой.
- **Мерная колба 100 мл** (метка на горле; ±0,1 мл): доведение до метки по каплям пипеткой.
- **Газометр / мерная трубка над водой** (цилиндр 100/500 мл, перевёрнутый в кристаллизатор): уровень воды падает
  по мере сбора газа, объём читается по шкале; потери при неплотной пробке (если ученик не закрыл — часть газа
  уходит, показание меньше).
- **Термометр** (−10…+110 °C, ±0,5 °C, столбик спирта растёт с инерцией) — 3D-предмет, который ставят в сосуд.
- **Фильтр + сушка + повторное взвешивание** (осадок): воронка, бумажный фильтр уже есть (`Funnel`, `FilterPaper`),
  добавь «сушильный шкаф/чашку» как шаг со временем (ускоренная анимация) и взвешивание фильтра до/после.
- Все показания публикуются в шину `labEvents` новым событием `{ type: 'measure', instrument, value, unit, at }`
  (только добавление в `labEvents.ts`) — для доски, учителя и журнала измерений.

### 1.3. Реализм, который нельзя упускать
- **Погрешности настоящие и видимые:** весы ±0,01 г, мензурка ±0,5 мл, газ над водой — ±2 мл и систематически
  немного меньше теории (растворимость, пробка), термометр ±0,5 °C. Результат опыта у ученика получается **не
  ровно** как в учебнике (например, 2,87 г AgCl по расчёту — на весах 2,85 г), и это **правильно**: сайт объясняет,
  почему (раздел «Сверка» ниже).
- **Температура и газ:** в классе 20–25 °C, не н.у. Объём газа в газометре показывается при комнатной
  температуре; ученик приводит к н.у. по формуле из учебника (или сайт показывает оба числа с пояснением).
  Задача решается в н.у., опыт честно показывает разницу (~8 %).
- **Масштаб:** учебник часто даёт килограммы/литры (0,39 кг Zn → 134 л H₂). На столе так не сделать. Правило:
  **ученик ставит опыт в уменьшенном масштабе (обычно в 10–1000 раз), сайт показывает коэффициент и помогает
  пересчитать** («в задаче 0,39 кг — это в 1000 раз больше, значит водорода будет 134,4 л»). Масштаб выбирай так,
  чтобы приборы читались: газ 50–450 мл, навески 0,5–5 г, растворы 20–100 мл.
- **Безопасность как в школе:** очки/перчатки (есть `gear`), работа с кислотами и Ba²⁺ в перчатках, нагрев —
  спиртовка/плитка, газы с запахом и ядовитые — только в вытяжном шкафу (`place: 'hood'`), а щелочные металлы,
  хлор, KClO₃, H₂S — **не для ученика** (поэтому их задач в списке нет). Правила ТБ — короткой карточкой перед
  опытом, нарушение (взял горячее без перчаток, налил воду в кислоту) — мягкое предупреждение учителя и штраф к
  звёздам, а не блокировка.
- **Что ученик видит и слышит:** шипение и пузырьки, муть, цвет раствора (голубой CuSO₄ бледнеет, когда Cu
  выделяется на железе), тепло на термометре, пар, запах — текстовой подписью («чувствуется запах…» только там,
  где безопасно), чёткая смена цвета CuSO₄·5H₂O синий → белый. Звуки из `labAudio` (есть `pour`, `fizz`,
  `bubble`, `glass-place`, `flame-on`…).

## Этап 2. 15 задач → 15 опытов

### Единая структура одной задачи-опыта (`src/data/labTasks/`)
```ts
type LabTask = {
  id: string                       // 'g8-zn-hcl-h2'
  grade: 7 | 8 | 9
  source: { page: number; section: string; kind: 'задача' | 'пример' | 'задание'; asInBook: LabText }
  statement: LabText               // условие как в учебнике (дословно, с исправленными опечатками — см. список)
  type: 'moles' | 'stoich-mass' | 'stoich-gas' | 'solution-w' | 'crystal-hydrate' | 'precipitate' | 'excess' | 'impurity' | 'mixture' | 'conservation'
  difficulty: 1 | 2 | 3
  answer: { value: number; unit: string; tolerance: number; alt?: {...}[] }   // как в учебнике
  labScale: { factor: number; note: LabText }      // 1 — как в задаче; 10 — в 10 раз меньше …
  substances: SubstanceId[]; instruments: InstrumentId[]; gear: Gear[]; place: 'bench' | 'hood'
  steps: LabTaskStep[]             // шаги опыта: инструкция, цель жеста, ожидаемое измерение, наблюдение, подсказка учителя, типичная ошибка
  measurements: MeasurementSpec[]  // что именно ученик снимает с приборов и в каком порядке
  calc: CalcStep[]                 // пошаговый расчёт (дано → уравнение → моли → ответ), с подстановкой ИЗМЕРЕННЫХ значений
  reconcile: LabText               // почему измерение ≠ расчёт (погрешность, температура, потери) — по этой задаче
  quiz: LabQuizQuestion[]          // 3 вопроса по опыту (не по формулам)
}
```

(взвешивание → растворение → реакция → сбор газа), если это не ухудшает реализм. Опыт регистрируется по чек-листу из
`lab-tasks-scouting/lab3d.md` §4 (все `Record<LabExperimentId,…>`, `rigTargets`, `BoardPlaceholder`, `Lab3DPage`, тест).

### Сценарий одной задачи-опыта (как это проходит ученик)
1. **Условие** (как в учебнике, с указанием страницы) + кнопка «Решить в лаборатории». Рядом — «Что понадобится»
   (приборы и вещества картинками) и правила ТБ (3 строки).
2. **Подготовка:** надеть защиту; взять со стеллажа/из шкафа нужное (всё остальное тоже доступно — ученик может
   ошибиться и взять не то; учитель мягко поправляет).
3. **Измерения и действия по шагам**, каждый — настоящим жестом (как в существующих опытах): положить на весы и
   довести до навески; отмерить мензуркой; слить; нагреть; собрать газ; отфильтровать; взвесить. Каждое снятое
   показание попадает в **журнал измерений** на доске («m(Zn) = 1,30 г», «V(H₂) = 480 мл при 22 °C»).
4. **Наблюдения** — подписи и доска (муть, цвет, температура, запах — текстом).
5. **Расчёт рядом с опытом:** доска показывает «Дано» уже с измеренными числами, ученик вводит ответ (поле с
   единицами); сайт считает по стехиометрии ОТ ИЗМЕРЕННОГО (ожидаемое с учётом масштаба) и сверяет с эталоном
   учебника.
6. **Сверка (reconcile):** три числа рядом — «Измерено», «Расчёт по измерениям», «Ответ учебника» — и объяснение
   разницы (погрешность прибора, температура газа, потери при фильтровании, масштаб). Это ключевой
   образовательный момент: разница — не ошибка, а физика.
7. **Итог:** звёзды (ТБ, аккуратность измерений — насколько близко к навеске, правильность расчёта), 3 вопроса
   викторины по опыту, запись в прогресс (см. этап 3), кнопка «Вернуться к задачам».

### Учитель (ИИ) в опыте
- Контекст `LearnTaskCoachContext` расширь полями `labTaskId`, `labMeasurements` (журнал), `currentStep`; выведи их
  в системный промпт коуча (`learnTaskCoachPrompt.ts`) и в локальный коуч (`learnTaskCoachLocal.ts`) — RU/EN/UZ.
- Учитель объясняет, что происходит на уровне частиц в момент действия (короткие фразы, 1–2 предложения), ловит
  типичные ошибки (мениск сверху, не дождался стабилизации весов, собрал газ с воздухом, забыл тару), **не называет
  ответ** (как сейчас в сократическом промпте).
- Голосовые фразы — через существующий TTS учителя (не обязательно, но желательно для «наживую»).
