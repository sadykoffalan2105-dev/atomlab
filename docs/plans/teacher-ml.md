# ИИ-учитель ATOMLAB: офлайн-мозг (teacher-ml)

Учитель отвечает без внешних моделей и ключей: «человеческий» слой (`src/learn/brain/human/`) →
база знаний (`src/learn/kb/`, BM25F по учебникам Kimyo 7–11 и карточкам) → локальный составитель ответа
(`src/learn/brain/dualMode/localAnswerComposer.ts`) → FAQ. Ниже — разделы по модулям.

## Энциклопедия (wf15): учёные и химия за пределами школы

**Что это.** Шард базы знаний из вступлений статей Википедии (ru + en/uz для ключевых тем): учёные-химики,
Нобелевские лауреаты, история химии, промышленность и технология, химия в быту, экология, биохимия,
материалы, аналитические методы, химия Узбекистана. Учитель отвечает по ним «как человек» — 3–5 предложений
живым тоном, но **ни одного факта не из текста статьи**.

**Лицензия.** Тексты Википедии распространяются по лицензии **Creative Commons Attribution-ShareAlike 4.0
(CC BY-SA 4.0)**. Поэтому:
- каждый фрагмент корпуса имеет `source: 'Википедия (CC BY-SA 4.0)'` (`Wikipedia (CC BY-SA 4.0)` / `Vikipediya (CC BY-SA 4.0)`);
- каждый ответ учителя из энциклопедии заканчивается подписью `[Википедия: <заголовок статьи> — CC BY-SA]`;
- при копировании этих текстов в другие продукты подпись и лицензию убирать нельзя.

**Как встроено (минимально).**
- `src/learn/kb/types.ts`: новый `KbChunkType` `'encyclopedia'`; `engine.ts`: нейтральный `typePrior`, тип ищется
  только по запросу `types: ['encyclopedia']` (как `'index'`); `shardFormat.ts` / `kb/index.ts`: шарды `wiki-a`, `wiki-b`
  грузятся лениво (dynamic import), в фоне — после всех школьных.
- `teacherKnowledge.ts` (`searchViaKb`): после школьных фрагментов вызывается `encyclopediaHitsFor(...)` — он добавляет
  фрагменты энциклопедии, если (а) вопрос «за пределами школы» (`кто такой`, `кто открыл`, `нобелевск`, `в промышленности`,
  `в быту`, `биография`, `who is`, `kim`, `kashf etgan`…), (б) в вопросе есть фамилия из словаря учёных,
  (в) школьные результаты слабые (пусто или лучший балл ниже `WEAK_SCHOOL_SCORE`). Школьные фрагменты всегда первыми.
- `learnTeacherRouter.ts` (`composeLocalTeacherReply`): один блок после `composeLocalAnswer` — если ответ учебника не уверенный
  или намерение «сильное» и среди фрагментов есть `type === 'encyclopedia'` → `composeEncyclopediaAnswer(...)` как уверенный ответ.
- `localAnswerComposer.ts`: фрагменты `encyclopedia` отфильтрованы (как `index`) — школьный составитель их не пересказывает.

**Как обновлять корпус.**
1. `npm run teacher:encyclopedia` — собирает список тем (категории Википедии + явный список ключевых заголовков в скрипте),
   качает вступления пачками по 20 (`prop=extracts`, `exintro`, `exchars=3000`), обрезает до ~2500 символов по границе
   предложения, чистит сноски/ударения/транскрипции, отбрасывает статьи с инструкциями синтеза (взрывчатка, яды, наркотики),
   добавляет EN-версии ключевых тем (langlinks → en.wikipedia, 1500 символов) и UZ, если есть. Кеш `.tmp/wiki-cache/` делает
   повторный запуск быстрым; для ускорения первой загрузки можно запустить параллельно `--prefetch k n`
   (например, 4 процесса `--prefetch 1 5` … `--prefetch 4 5` рядом с основным).
   Параметры: `--max N` — предел статей (по умолчанию 3600).
2. `npm run kb:index` — пересобирает все шарды, включая `wiki-a/wiki-b`, и `kb-manifest.json`.
3. `npm run test:teacher-encyclopedia && npm run test:teacher-dialog` — зелёные.
4. Добавить тему: заголовок статьи в `KEY_TOPICS` (с тегом) или категорию в `CATEGORIES` скрипта.

**Теги фрагментов** (`tags`): `scientist`, `history`, `industry`, `everyday`, `method`, `element`, `compound`, `concept`, `uzbekistan`.

**Что осталось / идеи.** Калибровка порога слабых школьных результатов на eval-наборе; чуть больше UZ-версий
(в uz-Википедии мало статей); связки «в N классе вы проходите…» расширить по оглавлениям учебников; второй проход
по статьям с коротким вступлением (брать начало первого раздела).
